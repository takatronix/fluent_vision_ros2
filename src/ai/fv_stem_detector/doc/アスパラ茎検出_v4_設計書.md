## アスパラ茎検出 v4 設計書（イベント駆動・低遅延）

作成: 2025-08-17 / 対象: `fv_stem_detector`

### 目的
- 遅延と無駄計算を排除し、YOLO検出イベントをトリガとして必要最小限の処理のみを実行する。
- 2D信頼度（YOLO）と3D信頼度（PCA等）を厳密に分離して表示。
- 同期・古さチェック・プロファイリングを標準装備し、最適化を継続可能にする。

---

## コア方針（イベント駆動）
- Color/Depthは「常時処理しない」。常に最新数枚を軽量バッファに保持。
- `Detection2DArray`（YOLO）が到着した瞬間にだけ、最新のColor/Depthペアを取得して処理。
- Color/Depthの時間差（slop）と古さ（max_age）を閾値でチェック。満たさなければスキップ（待機オーバーレイのみ）。
（これ本当にいりますか？、多少の差なので大丈夫かと思う）

- オーバーヘッド要素（cv::Matの不要なcloneや二重購読）を排除。

---

## 入出力とQoS
- 購読
  - `camera_topic`: `sensor_msgs/Image`（BGR8, best_effort）
  - `depth_topic`: `sensor_msgs/Image`（16UC1, best_effort）
  - `camera_info_topic`: `sensor_msgs/CameraInfo`（SensorDataQoS）
  - `detection_topic`: `vision_msgs/Detection2DArray`（best_effort）
- 発行
  - `output_annotated_image_topic`: 可視化画像（矩形・ラベル・root/tip/軸）
  - `output_detection_yolo_topic`: `fv_stem_detector/StemDetectionArray`（YOLO領域のcut-point）
  - `output_detection_fixed_topic`: 同上（固定領域使用時のみ）

---

## フレームバッファ/同期
- Color/Depthリングバッファ（各N=3程度）。格納: `cv_bridge::CvImageConstPtr`（ゼロコピー共有）。
- YOLO到着時のペア選定:
  1) `|t_color - t_depth| <= buffer.sync_slop_ms`（例: 30ms）
  2) `now - max(t_color, t_depth) <= buffer.max_age_ms`（例: 150ms）
  3) 満たすペアが無ければスキップ（処理しない）

---

## 処理パイプライン（YOLOトリガ）

### NewStemRegionリスト作成
1) YOLO受信（`onDetections`）
 　- 処理計測開始
  - Depth/Colorを受けつけないフラグをON（この期間に受信した画像は無視する）

   - 設定値（信頼度、最小の大きさw,h)をこえた、クラスID=０（アスパラ）を BBoxとYOLO `score` を `StemRegion` に保存（yolo_score)

   - StemRegionに、静的な矩形枠の領域を追加（yoyo_socore=0) BBoxのみ

-- ここからStemRegion数分ループ

2) ROI処理（方式は設定切替）
   - `2d_depth`: 2D形状抽出→最下点→Depthバリデーション→2Dpxと3D[m]
   - `pointcloud_linefit`: ROI→アプローチZ（中央値）→Z帯→PassThrough(y)→Voxel→SOR→PCA→root/tip/length/conf

　 - 根本World３D座標を作成保存。カメラのTFからWorldやMapからの絶対座標を作成する。
　 - 検出した時刻


3) オーバーレイ描画（必要時のみ）
   - 矩形（固定=青 / YOLO=緑）、アプローチ点（桃）、root=赤 / tip=黄 / 軸=水色
   - ラベル行:
     - 行0: `アスパラ#<ID> <YOLO%>` ← 2D信頼度
     - 行1: `2D信頼度: <YOLO%>`
     - 行2: `3D信頼度: <PCA%>`（pointcloud_linefit時のみ）
     - 行3: `アプローチ距離: <xx.x> cm`
     - 行4: `長さ推定(直線): <xx.x> cm`（pc_linefit時）
     - 行5: `処理: <xx.x> ms`（ROI時間）

-- ここまでStemRegion数分ループ

### 保存済みStemリスト（IDはっこうずみ）　と新規StemRegionの比較

・保存済みStemリスト（IDはっこうずみ）　と、近い、３D座標と、長さのアスパラガスの情報は、保存済みStemリストを更新
・新規の場合は、IDを発行して、保存済みStemリストに追加


4) メッセージ発行
   - `StemDetectionArray`（YOLO側）に 2Dpx と 3D座標 を格納  
5) プロファイリング出力
   - フレーム: `[frame] yolo=<K> total=..ms pair_age=..ms`
   - ROI(2D): `[roi2d] id=? morph=.. cc=.. pick=.. depth_fix=.. total=..ms`
   - ROI(3D): `[roi3d] id=? make=.. pass=.. voxel=.. sor=.. pca=.. total=..ms pts=A/B/C conf=.. len=..cm`

## 低遅延のための実装要点
- 早期リターン徹底
  - 出力購読者が0なら処理しない
  - ペア不成立・古すぎるDepthのときは処理しない
- コピー削減
  - `cv_bridge::toCvShare` を基本にし、`cv::Mat::clone()` は必要場所のみ
  - ROI処理は `Rect` でスライス参照を優先
- メモリアロケーション抑制
  - 内部バッファを再利用（`reserve()` など）
- 並行実行
  - `MultiThreadedExecutor` 前提、YOLOイベント→ワーカースレッドへディスパッチ
  - `event.skip_if_busy` オプションでバックプレッシャー（渋滞時に間引き）

## パラメータ（v4）
```yaml
# 例: /ros2_ws/config/fv_stem_detector_d405.yaml
event:
  mode: "yolo_trigger"        # yolo_trigger | legacy_sync（後方互換）
  skip_if_busy: true           # 実行中は新規イベントを間引く
buffer:
  max_age_ms: 150              # Color/Depthの許容古さ
  sync_slop_ms: 30             # Color-Depth時間差の許容
profile:
  enable: true
  every_n: 10
overlay:
  show_region_labels: true
  label_text_color_bgr: [255, 255, 255]
  approach_point_color_bgr: [255, 0, 255]
  root_color_bgr: [0, 0, 255]
  tip_color_bgr: [0, 255, 255]
  axis_line_color_bgr: [255, 255, 0]
detection:
  method: "pointcloud_linefit"  # or "2d_depth"
depth_band:
  enable: true
  minus_m: 0.05
  plus_m: 0.05
voxel:
  leaf_m: 0.0035
sor:
  mean_k: 50
  stddev_mul: 1.2
pca:
  min_confidence: 0.60
length_gate:
  min_length_m: 0.10
  max_length_m: 0.40
```

- 固定領域: `region.id` をそのまま表示IDとして利用
- YOLO領域: 前回矩形とのIoUで簡易追跡（v4初期）。将来は3Dベクトルトラッカ導入（`doc/3D_ID管理設計_v2.md`）

## エラーハンドリング/健全性
- `camera_info` 未受信時は3D出力をNaNにするが処理は継続（警告スロットル）
- Depthの型/サイズ不一致は即スキップ
- YOLO未着時は最後の矩形を短時間ホールド（フェード）
